## 🚀 전달 방법 (상황별)

**① 디자이너에게** — ZIP 하나를 드라이브/메일로 전달하면 됩니다. 코드 볼 필요 없이 `미리미소-웹앱.html`을 브라우저로 열어 화면을 확인할 수 있습니다.

**② 개발자에게** — GitHub 저장소에 올려 공유하는 것을 권장합니다 (변경 이력 관리). 여의치 않으면 ZIP 전달도 가능하며, 작업 후에는 소스 폴더째로 돌려받으세요.

**③ 간단히 보여만 줄 때** — 완성본 HTML 파일 1개만 보내면 됩니다. 설치 없이 바로 실행됩니다.

데모 진입 방법: 파일 열기 → 역할 카드 선택 → 동의 체크 → 시작. 초대코드(계정 모드): 의료진 `MIRI-CLINIC-2026` · 기공소 `MIRI-LAB-2026` · 환자 `MIRI-PAT-2601`

## 🎨 Figma 작업 절차

1. Figma에서 **html.to.design** 플러그인 설치 (무료)
2. `미리미소-웹앱.html`을 브라우저로 열고, 플러그인으로 화면별 임포트 → 편집 가능한 프레임으로 변환
3. `디자인토큰.md`의 색상·간격을 Figma Variables/Styles로 등록
4. `화면목록.md`를 체크리스트 삼아 25개 화면 커버 여부 확인
5. 확정안은 Figma 링크로 공유 (개발자는 Dev Mode로 수치 확인)

## ✨ Google Stitch 작업 절차

1. [stitch.withgoogle.com](https://stitch.withgoogle.com)에서 테마 설정 — Primary `#27AE8D`, 배경 `#F4F6F9`, 폰트 Noto Sans KR
2. `Stitch-프롬프트.md`에서 화면별 프롬프트를 복사해 생성
3. 기존 느낌을 유지하려면 현재 앱 스크린샷을 참고 이미지로 첨부
4. 결과는 **Figma로 내보내** 다듬고, 코드는 시안 참고용으로만 사용

권장 흐름: **현재 앱 캡처 → Stitch로 변형안 탐색 → Figma에서 확정·시스템화 → 개발 전달 → 기존 앱에 반영**

## ⚠️ 작업 시 반드시 지킬 것

1. **비진단 고지 유지** — 화면의 "진단이 아닙니다·교육용 데모" 문구는 규제상 필수, 삭제·축소 금지
2. **가상 데이터** — 모든 환자 정보는 데모용 가상 데이터. 실제 개인정보를 넣지 마세요
3. **단일 파일 빌드** — 최종 결과물은 단일 HTML 268KiB(274,432B) 이내로 빌드됩니다. 이미지·폰트 에셋은 가볍게 유지하세요 (현재 274,322B 사용 중)
4. **내부 계약 유지** — 데이터 저장 키, 서버 API, 화면 이동 구조를 바꾸면 기존 기능이 깨집니다. 디자인 레이어(색상·배치·컴포넌트 모양) 중심으로 작업하세요
5. **자동 검증** — 개발 반영 후에는 스모크 테스트 1,515개로 전 기능 회귀를 확인합니다 (테스트 통과가 완료 기준)
